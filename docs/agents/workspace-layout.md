# Workspace layout

本仓库把「东西该放哪儿」拆成两个问题：这份材料**是什么高度**，以及它**是不是交付物**。
两问定位置，不问「给 AI 看还是给人看」—— 那个判据在协议路径面前不成立。

> **语言约定**：本文件是给人读的，**中文优先**。目录名、文件名、协议字段（`Status:`、`Type:`、`Blocked by:`、
> `## Comments`、`## Answer`、`CONTEXT.md`、`.scratch/`、`docs/adr/`）**保持英文**，因为它们由其他 skill 解析。

## 五个层，一眼定位

| 层 | 回答的问题 | 谁读 | 进 git？ |
|---|---|---|---|
| `projects/<slug>.md` | 这是什么、解决什么问题、边界在哪 | 几个月后忘光的你 | 是 |
| `docs/<effort>/` | 具体怎么做的（事实核查、调研、报告） | 要继续这项工作的人 | 是 |
| `.scratch/<effort>/` | 从哪断的、下一步做什么（spec、ticket、map、NEXT） | 要接着干的人 | 是 |
| `archive/<case>/` | 当时到底跑过什么（脚本、日志、快照） | 几乎没人，除非要复查 | **否** |
| `tools/<name>/` | 会被第二个 effort 再用的程序 | 下一个 effort | 是 |

判据是**高度**（总览在上、细节在下）加一条**去留线**：将来还会被**引用或重读**的进受 git 管理的层，
只是**证明当时做过什么**的进 `archive/`。

## 代码放哪儿

产品代码住在 `src/`：领域逻辑（词条、链接、小结论、留档）与界面层（网页 demo、将来的手机端）分开，
共用同一套领域逻辑。`src/` 的**具体结构由 spec 定型**，本文件只锁一条 —— 代码不进 `docs/`
（`docs/` 写「怎么做的」，代码是「做出来的东西」），也不进 `tools/`（那是给 effort 用的可复用程序）。

## 协议路径 —— 一律不动

这些位置由 skill 硬编码解析，改动会打断主流程：

`AGENTS.md`、`CLAUDE.md`、`CONTEXT.md`、`CONTEXT-MAP.md`、`.agents/skills/`、`.claude/skills`、`.git/`、
`.scratch/<effort>/spec.md`、`.scratch/<effort>/issues/<NN>-<slug>.md`、`.scratch/<effort>/map.md`、
`docs/agents/`、`docs/adr/`

**新增一层永远比移动一层便宜。** skill 是本仓库自带的（`.agents/skills/`，由 `skills-lock.json` 锁定版本），
`.claude/skills` 只是指向它的 junction —— 两者都不许移动。

## `projects/` —— 每 effort 一份总览

**一 effort 一份，平铺。** 文件名用 slug：`projects/<effort-slug>.md`，与 `.scratch/<effort-slug>/`、
`docs/<effort-slug>/` 三层同名，互相能对上。文档内 H1 用中文名。

**不加英文对照件。** `AGENTS.md` 的语言策略要求重要文档出中英两份，但总览是**唯一只为你的记忆服务**的文档种类，
英文对照件的存在理由（交给别的模型或协作者）在这里不成立，而维护两份会让它更快腐化。

**什么时候写。** 在 effort 收尾时写 —— 所有 ticket 都 `resolved` 之后，不打断中间的流程。

**一个 effort 是什么。** 一个有名字的工作单元，通常对应 `.scratch/<slug>/` 下一个目录。
「某个 effort 的产物后来长成了独立工具」的情况仍算在原 effort 名下，工具级别的细节由
`tools/<name>/README.md` 承载，总览不复述。

### 总览模板

复制下面这块，把尖括号替换掉。**用平实语言** —— 目标是三个月后的你能在五分钟内重新理解这个项目。

```md
# <中文名>

<一句话：这是什么。>

## 解决什么问题

<当初为什么会做它。没有它的时候是什么状态、会出什么麻烦。>

## 边界

- **管**：<它会做的事>
- **不管**：<它明确不做的事 —— 这条往往比上一条更有用，能挡掉「那它能不能顺便…」>

## 容易忘的几点

<这个项目里最容易在几个月后被问起、但细节文档里埋在深处的问题，一问一答写下来。>

- **<问题>**：<答案>

## 现在在哪

- 总览：本文件
- 细节：`docs/<effort>/`
- 工作材料：`.scratch/<effort>/`（含 `NEXT.md`，从哪断的看它）
- 代码：`src/`
- 工具：`tools/<name>/`
```

「容易忘的几点」是这个模板里唯一不能省的部分 —— 它是总览存在的理由。判断标准很直接：
**如果这个问题你答得出来，就不必写；如果它是你三个月后一定会问、而现在的文件里要找半天的那种，就写。**

## `docs/` —— 按 effort 收拢

- 任何 effort 的产物进 `docs/<effort-slug>/`，slug 与 `.scratch/` 下的一致。
- `docs/` 根目录只留**工作区级文档**，本仓库目前只有一份：`Matt-Skills-使用指南.md`（25 个 skill 怎么用）。
  正文级材料在 `docs/agents/`（协议路径）与 `docs/<effort>/` 里；要往根加文档，先想清楚它为什么不属于任何一个 effort。
- `docs/agents/` 与 `docs/adr/` 是协议路径，不受这条影响，原地不动。

## `tools/` —— 只收会被第二次用到的程序

单个文件的工具直接放在 `tools/` 根（如 `tools/check-workspace.mjs`）；多文件的工具各自一个目录，
目录里带 `README.md`。索引表在 [`tools/README.md`](../../tools/README.md)。

**晋升规则（三条）：**

1. 只服务一个 effort 的脚本 —— **跟案走**，进 `archive/<case>/`，不进 `tools/`。
2. 在**第二个 effort** 里被再次需要 —— **晋升**进 `tools/`，此时补 `README.md`。
3. **写新脚本之前先读 `tools/README.md`**，能复用就别重写。

「晋升」是凭结果判断的，不是凭预判 —— 一个脚本在第二个 effort 出现之前，没有人知道它会不会被复用。

## `archive/` —— 不进 git 的副产物

`archive/<case>/` 收一次性案子的脚本、日志、快照、原始粘贴。整个 `archive/` 在 `.gitignore` 里，
所以往里面丢大文件不会污染仓库历史。三条规则见 [`archive/README.md`](../../archive/README.md)。

**归档的前提是「先瘦身」**：几百 MB 的二进制、临时数据库在归档**之前**删掉，不要跟着搬。

**归档件按只读记录对待，内部路径故意不改写。** 案例里写的命令原文是当时实际执行过的记录，
改成新路径会掩盖真实执行历史，比留下失效路径更糟。读归档件时按「文件就在同目录下」理解即可。

**报告不跟案走。** 写出来的报告（诊断报告、调研报告）是**交付物**，留在 `docs/<effort>/`；
只有脚本、日志、快照这些**副产物**进 `archive/`。

**被文档引用的脚本跟文档走。** 一个脚本如果被某份留在 `docs/` 的文档**按名字引用**，
它就属于**产物**而不是副产物 —— 丢进 `archive/` 等于让被引用者消失。

## 检查

约定写完还会回归，所以有 `tools/check-workspace.mjs`：**按需运行**，不自动触发、不拦截任何操作，
只在收尾时跑一次打印违例清单。

```bash
node tools/check-workspace.mjs      # 跑检查器
node tools/check-workspace.test.mjs # 跑它的测试（不要用 node --test，受限沙箱里会 spawn EPERM）
```

它检查的是**布局**，不是内容：根目录有没有多余文件、`.scratch/` 里有没有非 tracker 目录、
`docs/` 根有没有 effort 产物、`archive/` 里有没有大文件。发现违例时它只报告，怎么处置由你定。

这个仓库的检查器是从 `DSH` 工作区移植过来的，常量按本仓库实情改过（允许的根文件、`docs/` 根允许的文档）。
再移植到别处时，跑测试就会告诉你改漏了什么。
