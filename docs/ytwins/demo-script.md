# 三幕 demo 的演示脚本

> 这是**给你自己上台用的脚本**，不是给用户看的说明，也不是产品需求。
> ticket 13 要求「三幕的演示脚本以中文写进仓库，供日后复现」——这一份就是它：
> 每一步输入什么、看什么、预期看到什么，以及重跑和救场怎么做。
> 三幕跑在**预置素材**上，同一套素材也是领域测试用的那一套（`src/domain/preset.ts`）。

## 0. 一句话

往输入框里随口丢碎片，**不选类型、不填时间**；它自动分成事项与留档，隔几天还能问得出准确的事实
并指出出自哪次投递；再丢一句情绪，它用不确定的语气浮出一条小结论，并列出背后支撑的**词条**。
全程不需要账号，页面上写清哪部分数据会离开这台机器。

## 1. 怎么起

演示走**预置 provider**（`YTwins_PROVIDER=demo`）：不联网、不花 key、每次说同一句话。
真实 provider 仍是产品的默认（详见 §7），但**演示不要用它** —— 它的措辞每次略有不同，
而这张 ticket 要的是「连续重跑结果不变」。

```powershell
# 仓库根目录，PowerShell
$env:YTwins_PROVIDER = "demo"
npm run server            # 默认 http://127.0.0.1:5273
```

打开 `http://127.0.0.1:5273/demo.html`，页面底部会出现「三幕 demo」一节（里面就是下面三句台词）和
「哪些数据会离开这台机器」一节。

> **地址在 ticket 15 之后变了。** 根路径 `/` 现在是**产品本身** —— 只有一个输入框的那一页（见 §8），
> 三幕页搬到了 `/demo.html`，页面内容一行没改。三幕是**演示与回归的参照**，产品是合体那一页。

**演示模式默认用自己的库**：`data/demo.sqlite`。它和平时用的 `data/ytwins.sqlite` 是两个文件 ——
演示里那个「重新开始演示」按钮清空的是前者，不会碰到你平时丢进去的东西。启动日志里会写明这一点。
要指定别的库就设 `YTwins_DB`，那时以你指的为准。

**页面上会自己说明这件事**：演示模式下，第一幕与第三幕的输入框上方各有一句「这个服务只认页尾那三句
台词」，页尾的 demo 一节也写着同样的话 —— 因为它对台词以外的内容**读不出任何词条、也不会有事项**，
只回一句「记下了。」，那看起来像产品坏了，而不是像一场演示。真实模式（产品的默认）下这句话不出现。

演示前点一下底部「**重新开始演示**」→ 确认（两步，和删除一样），库里就只剩预置好的素材：
关于期末那件事的两句、关于睡不好那件事的两句。**这一步是必须的** —— 三幕要求的是「同一件事被提起
三次」，这两句就是前两次。

已经构建过页面就不必重新构建；改过 `src/web/` 才需要 `npm run build:web`。

## 2. 三幕

页面顶部三个页签（丢 / 问 / 浮）就是三幕（这一页在 `/demo.html`）。

### 第一幕：丢

- 台词（**演示模式下，输入框里的占位文字就是这一句本身** —— 连「比如：」之类的前缀都没有，
  照抄或粘贴整行即可；多一个字都落不到预置素材上，第一幕就会跟着塌）：

  ```text
  老师今天讲了期末怎么算分：平时分 40%，期末考 60%，下周三交提纲，好烦
  ```

- 不做的事：**不选类型、不填时间、不打标签**，就是丢出去。
- 预期看到：
  - 一句回应：「听着，事情全堆在一起，心里挺堵的。」（有情绪时先接情绪）
  - 「接住了什么」里这次投递下挂着一条**事项**「下周三交提纲」，到期时间是**下一个周三 09:00**
    （素材说的是「下周三」，由代码按当天算出来；换一天演示，日期跟着换）
  - 这次投递抽出 5 个**词条**（都是你原话里的说法）：「期末怎么算分」「平时分 40%」「期末考 60%」
    「下周三交提纲」「好烦」
  - 输入框下面还会顺带浮出一句：「我不太确定：你最近好像有几件事堆在一起，心里一直不太顺。」
    —— 这是同一个 moment（情绪投递会尝试浮现），第三幕演示的是**另一件事**浮出的那一条。

### 第二幕：问

- 先点「**设为三天后**」（时间基准就成了「几天后」的视角），再问：

  ```text
  期末怎么算分
  ```

- 预期看到：
  - 答案：「平时分占 40%，期末考占 60%。提纲还有 N 天到期。」—— N 由「三天后」这个视角与提纲的到期日
    算出来，所以它跟着你提问的时刻走（同一次演示里重跑，N 不变）。
  - 「来自这几次投递」里是**那一次**投递的原文，逐字可核对。预置素材里前两次说的话刻意不含
    这个问题要找的字符串，所以出处就是第一幕刚丢的那条 —— 答得出、也查得到。
- 不填时间基准直接问也可以，答案里的天数会按「现在」算。

### 第三幕：浮

- 台词：

  ```text
  这周总是睡不好，白天没精神，晚上躺下又清醒，有点撑不住
  ```

- 预期看到：
  - 一句回应（这次也带情绪，所以先接情绪）
  - 浮出：「我不太确定：你最近睡得不太好，白天也提不起劲。」
  - 下面列出**支撑它的 3 个词条**：「睡不好」「没精神」「躺下又清醒」，以及「为什么这么说」的四个数
    （被提起 3 次 · 3 个词条 · 跨 0 天 · 平均连接强度）—— 措辞的强弱就是从这几个数读出来的，
    所以「为什么这么说」是能回答的，而不是模型当场感觉了一个语气。
- 这一条是**另一件事**，和第一幕那条不是同一条：`好烦` 那件事已经在第一幕听过了（7 天冷却），
  睡不好这件事是新的，所以它现在才浮出来。

## 3. 连续重跑

同一套素材、同一条链路、同样的结果。台下要求再来一遍时：

1. 点页面底部「**重新开始演示**」；
2. 确认「清空并重新开始」（两步确认，因为它会清空整个库）；
3. 从第一幕重来。

结果与上一次逐字相同（除了投递的时刻）。可重复性本身就是被检查的：领域测试里有一条
「三幕连跑两遍、结果相同」，`tools/e2e-ticket-13.mjs` 也在真 HTTP 上跑了两遍并比对。

## 4. 数据边界（页面上也写着）

「哪些数据会离开这台机器」那一节由**服务端按这台机器实际的接线**读出来（`/api/privacy`），
不是页面里写死的文案 —— 页面写一套、服务端跑另一套就等于这条披露本身在骗人。

- **演示模式（本脚本）**：什么都不离开这台机器。答话、判断、embedding 全部在本机算出来，不联网、
  不花 key，key 也不需要配。
- **真实 provider（产品的默认）**：**原文**（你丢进来的话、你问的问题、以及为了让模型答得出来而
  挑给它的那几段原文与词条）会送去云端 LLM（默认 `api.deepseek.com` 的 `deepseek-flash`）；
  embedding 在本机 CPU 上算，词条不出机器。API key 只在仓库根的 `.env` 里，页面拿不到。
- 读不到这段时会说「这次没读到数据边界」——**不会**显示成「什么都不出去」。

## 5. 台下可能问到的

- **为什么「重新开始演示」是两步的？** 因为它是产品里唯一会一次清空全部素材的动作。删除那条路
  （每条投递旁边的「删掉这次投递」）也是两步的：先告诉你会连带什么，再由你选。
- **为什么第一幕就浮了一句？** 浮现的时机是「情绪投递」或「你主动问」，第一幕那句带情绪，所以它
  当场就会试着说一句。第三幕演示的是**另一件事**浮出的那一条 —— 同一轮最多一条，每件事 7 天冷却。
- **为什么第三幕的「再丢一次第一句」按钮还在？** 那是给「不预置、全靠现场丢」的走法留的：同一句
  丢到第三次才跨过阈值。预置素材的走法不需要它。
- **第三幕里「问你一句：你觉得我最近怎么样」为什么常常答「先不重复」？** 那要凑得出**两条及以上**
  还没听过的小结论才成一句**答案**；三幕跑完时两件事都已经各自浮过一次了，于是在冷却里。这条链的
  回归在 `tools/e2e-ticket-11.mjs`，不在三幕的脚本里。
- **为什么事项的日期是「下周三」算出来的，而不是写死的？** 素材里说的就是「下周三」，写死一个日期
  过几天就会变成「已过期」。真实 provider 也是把相对时间按今天换算，所以这更接近真的。

## 7. 两个 provider，跑过一遍再定（2026-09-17 的记录）

ticket 13 开工前跑过两条路（记录在 ticket 13 的 `## Comments`）：

- **预置 provider（演示路径）**：逐字可重复、离线、免费，且「预置素材 = 领域测试用的素材」这条
  要求只有它能满足。
- **真实 provider**：链路是真的（真 LLM 读原文、真本地 embedding 算向量），但措辞每次不同、
  要 key、要联网，而且每件事要说满三次才跨阈值这件事在真实链路上要现场丢很多句。

所以：**演示走预置 provider，产品默认仍是真实 provider**（`YTwins_PROVIDER` 不设就是真实）。
真实链路的手工冒烟用 `npm run smoke`。

## 8. 产品本身：一个框（ticket 15）

同一个服务上的另一页：根路径 `http://127.0.0.1:5273/`。**只有一个输入框** —— 没有页签、没有单独的
「问」入口、没有类型／时间控件。是碎片、是在问一件**留档**里说过的事，还是问一句关于**你自己**的话，
由**领域**判断（`src/domain/routing.ts` + 端口的 `judgeQuestion`），页面只把领域给了什么摆出来。

四种输入各看一眼（碎片分带情绪与不带情绪两种，所以下表是五行；演示模式下只认台词，
前三行里也只有第一幕那句与第二幕那句能演）：

| 丢什么 | 预期看到 |
|---|---|
| 一句碎片（不带情绪） | 只有一句回应，外加抽出的事项与词条 |
| 一句碎片（带情绪） | 上面那些，**再加**浮出来的那一条 |
| 问一件确实说过的事（如「期末怎么算分」） | 「留档里是这么说的」+ 答复 + **来自这几次投递**的原文；这一轮**不会**塞一条判断 |
| 问一句没说过的事（如「上周的会议纪要放哪了」） | 明确说留档里没有相关的记录；同样不塞判断 |
| 问一句关于自己的话（如「你觉得我最近怎么样」） | 「把几条汇成的一句」（两条以上小结论时），凑不出就退回只浮一条 |

**分不清时不猜**：判不出是问题，就不当问题 —— 宁可少说一句，也不把自言自语当成提问。代码先看问句
形态（问号、「怎么／为什么／哪」这类说法），拿不准才交给模型；形态是「吗／呢」结尾时，还要看这次投递
的**输入类型**：带情绪的那种仍算碎片（「下周三交提纲吗」是自言自语，不是问题）。

**这一页在演示模式下能演什么**：第一幕那句（碎片，带情绪 → 浮出）和第二幕那句提问（→ 追溯、指出出处）
都能演；**问关于自己的话演不了**（预置表里没有那一句，读不出就是碎片），台词以外的内容也一律读不出 ——
页面在输入框上方会自述这件事。要看完整的四种分发，用真实 provider。

**这一页不存对话**：追溯的答复与浮出来的那一条属于**说出口的那一刻**，只在该次会话的页面上；刷新之后
留下的是投递本身（原话、回应、事项、词条）与「画像」。这是有意的：产品是陪伴，不是陪聊。
