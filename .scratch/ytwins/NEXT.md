## 已冻结的决定（不要再问一遍）

- **demo = 三幕**（2026-09-14 确认；将来用实践检验是否增减）：
  ① **丢** —— 往输入框丢一段无格式的杂乱输入（含老师讲的评分标准 + 一句情绪），不选类型、不填时间，
  系统自动分出**事项**与**留档**；② **问** —— 以「几天后」的视角问「期末怎么算分」，准确答出，并指出源自哪次投递；
  ③ **浮** —— 再丢一句情绪化输入，浮出一条**不确定语气**的小结论（用预置的足够词条支撑）。
- **demo 不包含**：注册、多用户、移动端、冲突检测与提醒可靠性、完整日历 UI、真实 AI 生成优化。
- **数据**：原文全存（不存摘要）；删除级联并明确告知（「有 2 条小结论是从它来的，一起删吗」）；
  demo 与 MVP **纯本地、无账号**。
- **回应方式**：四本育儿书提炼出的规则是**硬约束**（见 `docs/ytwins/parent-voice-principles.md`，
  末尾有一节「产品作者补充的规则」是非书本来源）；只用中文；只摆事实、不贴标签。
- **浮现**：只在用户情绪投递、或用户主动询问时尝试；同一主题 **7 天冷却**；每轮最多一条；一律不确定语气
  （「你似乎…」「你最近…」）。
- **结论链**：默认只读；用户只能标「不对」和补一句自己的话（那句话本身又是一次投递）；
  不做打分、点赞、批量反馈 —— 那是训练无感的红线。
- **链接不需要训练模型**（调研已确认，见 `docs/ytwins/memory-linking-research.md`）：用预训练 embedding +
  相似度阈值（三段式，灰区才调 LLM 判定），外加「共同出现在同一次投递」这条零模型硬边。
- **2026-09-15 写 spec 时确认的三条**（不要再问一遍）：
  ① **测试 seam 两处**：领域核心的 interface（最高 seam）+ AI provider port（唯一外部依赖 seam）；
  存储与网页界面不上 seam。② **demo 默认 AI 组合**：云端 LLM（DeepSeek `deepseek-flash`，JSON 输出）
  + 本地 embedding（transformers.js 的多语言小模型，离线、无需 key）。③ **形态**：本地 Node server
  + SQLite + Vite 网页；领域逻辑与界面层分居 `src/` 下两个顶层目录。
- **2026-09-15 拆 ticket 时确认的一条**：切法保持**垂直切片**（每张从存储切到页面），**不**先做完整前端
  再用假数据演示。理由：前端取数层要依赖尚未定型的领域核心 interface，先做必然重写；而「先简单后复杂」
  的诉求已由 AI provider port 满足（01–11 用假 provider 定型，12 才换真实实现，领域逻辑零改动）。
  唯一的吸收是把三幕页面骨架提前到 01（见上）。
