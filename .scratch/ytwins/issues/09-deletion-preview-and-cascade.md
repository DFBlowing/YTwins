# 09: 删除 —— 先告知，再级联

**What to build:** 删除一次**投递**时，系统先明确告知「有 N 条**小结论**是从它来的」，由用户决定是一起
删掉还是只删原文；用户确认后执行删除，且删除一旦发生，它的正文不再出现在任何**追溯**结果或**结论**里 ——
「删掉」是真的删掉，不留孤儿行。

**Blocked by:** 05（阈值汇集 —— 第一条小结论、画像与结论链）、07（追溯 —— 问一件旧事，答得准并指出出处）

**Status:** ready-for-agent

- [ ] 删除前先返回预览：受这次投递影响的**小结论**数量（例如「有 N 条小结论是从它来的」）。
- [ ] 在任何删除真正发生之前，用户必须做出一次明确选择；不存在静默或默认删除。
- [ ] 选择「一起删」时，受影响的**小结论**被级联删除，不留孤儿行。
- [ ] 选择「只删原文」时，投递与留档被删除，而衍生出的小结论按既定口径保留或标记失效（实现时二选一并写清理由），且不会崩溃或留下悬空引用。
- [ ] 级联删除之后，**追溯**不再返回该投递的任何内容。
- [ ] 级联删除之后，**画像**与**结论链**里不再残留它的痕迹。
- [ ] 级联删除之后，指向它的**词条**与**链接**一同清除，不留孤儿行。
