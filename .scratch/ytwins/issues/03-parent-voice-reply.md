# 03: 回应方式 —— 情绪优先与机械规则校验

**What to build:** 每次投递都能拿到一句简短的**回应**。输入里含情绪时，回应的第一句是情绪回应，而不是
信息、结论、建议或提问。那些可以机械判定的规则由**代码校验**，不指望模型自觉：校验失败时**重生成一次**，
第二次仍失败则**降级为一句安全的最短回应**（按输入是否含情绪选择「情绪回应」或「记录确认」），
保证违规内容不出现在用户面前。

**Blocked by:** 02（接住的结构 —— 自动分出事项与留档）

**Status:** ready-for-agent

- [ ] 含情绪的投递，其**回应**的第一句是情绪回应（替用户把感受说出来），不是信息、结论、建议或提问。
- [ ] 不含情绪的投递不硬凑情绪回应。
- [ ] 代码校验以下机械规则：不超过 3 句、约 60 字；不以「为什么」起问；单轮最多一个问句；无禁用词表；无亲昵称呼；无「但是／不过／至少」这类转折收尾。
- [ ] 校验失败时恰好重生成一次；第二次仍失败则输出**降级的安全回应**，且该回应自身通过全部机械校验。
- [ ] 假 provider 提供一个「故意违反回应规则」的脚本，测试用它走通「校验 → 重生成一次 → 降级」整条路径。
- [ ] 回应一律为中文。
- [ ] 需要判断的规则（是否先接情绪、是否在给建议、是否贴标签、是否替用户做决定、是否做未被索取的提醒、是否把话题转向「开心的事」）通过写进 AI provider 的指令来约束，并由测试对**行为性质**做断言。
- [ ] 用户说「不想说 / 算了 / 没事」时停止追问，只留一句最短的在场声明。
- [ ] 只有用户明确问「怎么办」、或用户自己已说出一个方向时才给建议，且最多一条。
