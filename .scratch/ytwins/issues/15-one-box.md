# 15: 一个框 —— 把丢、问、浮收成一件用户做的事

**What to build:** 用户只看到一个输入框：随口丢什么都进同一个框。分不清"这是在丢碎片，还是在问一句"是
**产品**的事，不是用户的事 —— 所以这件事不该由用户选，也不该由页面猜。原话永远先成为一次**投递**
（原文保真落库），然后产品自己决定这句话之后还要说什么：问的是**留档**里的事 → **追溯**（照实陈述、
指出出处）；问的是关于**用户自己** → 同一个 moment 给**答案**；只是一句碎片 → 只有**投递**自己的回应，
外加（若带情绪）**浮**出来的那一条。三幕页原样保留，作为演示与回归的参照。

**Blocked by:** 07（追溯）、11（答案）、13（演示页与预置素材）

**Status:** ready-for-agent

- [ ] 一个输入框：没有页签、没有单独的「问」入口、没有类型／时间／标签控件。
- [ ] 任何原话**先落库**（`drop` 的保真承诺不变），用户当场拿到一句**回应**，以及（有的话）**事项**与**词条**。
- [ ] **分发是领域的规则，不是页面的 if。** 页面只把原话交给领域，然后照领域给的结论显示 ——
      落成一个**任务形状**的操作（名字按 `CONTEXT.md` 的词定：投递／追溯／浮现），
      而不是让页面自己拼 `drop` + `recall` + `surface` 三次调用。
- [ ] **事实问题**：答得出就照实说并指出出处；答不出就明确说没找到。
      **问事实的时候不许塞一条判断** —— 这一轮不触发浮现。
- [ ] **关于用户自己的问题**：走那个 moment 给**答案**（多条小结论汇成一句）；凑不出两条时退回**浮**出
      仅有的那一条（11 定的退路不变）。
- [ ] **碎片**：不追问、不装懂；带情绪时照旧**浮**一条（06 的时机、每轮最多一条、7 天冷却都不变）。
- [ ] **分不清时不猜**：判不出是问题，就不当问题 —— 宁可少说一句，也不把自言自语当成提问。
- [ ] **端口要跟上**：判定「这句是不是在问、问的是哪一类」要有出处（新增端口方法，或在
      `parseQuestion` 上扩语义 —— 实现时定）；**两个 implementation 都要实现**，
      12 的 `satisfies Record<keyof …, true>` 会强制穷尽性，漏一个就编译不过。
- [ ] **页面**：一条**投递** = 原话 + 它的回应 + 事项 + 词条 +（如果有）追溯的答复与出处／浮出来的那一条；
      下面仍是「接下来要做的 / 连起来的词条 / 画像」。
- [ ] **三幕页一行不改**，仍然是演示与回归的参照；`tools/e2e-ticket-13.mjs` 与三幕相关的检查不动、仍全绿。
- [ ] 领域测试新增 2–3 条钉住分发（碎片不触发答案、事实问题不触发浮现、关于自己的问题给答案）；
      `src/domain/**` 的**既有**检查一行不改仍全绿。
- [ ] DOM 不自动测（spec 的测试决策如此），跨层取数用真 HTTP 的 e2e 覆盖（`tools/e2e-ticket-15.mjs`）。
- [ ] **人工验收一遍**：丢 3 句碎片（其中一句带情绪）、问一件确实说过的事、问一句关于自己的话、
      问一件没说过的事 —— 四种各看一眼。

## Comments

**2026-09-17 — 开票**

**作者的原话**（2026-09-17）：「我想象中的这个产品，应该是将**丢、问、浮**三者合为一体的，即用户只会看到
一个界面，具体是丢、问、浮不是用户应该关心的。」

**确认这是设计，不是新要求。** 三幕是**演示装置**：spec 里「demo 三幕」那组故事的说话人写的是
「**作为演示者**，我希望…」（62–65），`NEXT.md` 在 2026-09-14 冻结这条时也写着「将来用实践检验是否增减」。
把三者合成一个框，正是 `CONTEXT.md` 的**无感**（输入无感：丢进来就行）与 spec 用户故事 6
（**输入类型**由系统内部判断、**全程不让我感知、也不要求我选择**）的直接推论；spec 用户故事 59
（将来换手机端时界面整个换掉、领域逻辑不动）也正是为什么三个页签可以退场。

**作者拍板：两份界面都留。** 三幕页做**演示与回归的参照**（台上要一幕一幕演，`demo-script.md` 就是照它写的），
合体版是**产品本身**。两者共用同一个**领域**接口，互不影响。

**为什么这不是"换个皮"。** 分发的判断 —— 「这句是不是在问」以及「问的是留档里的事，还是关于我自己」——
是一条**产品规则**。本仓库反复写下的原则是：页面不做决定，只显示领域决定了的事（`createHandler` / `main.ts`
里每一处读取都照抄领域的答案）。所以它必须落在**领域**里，这一票因此有实质内容；但 `src/domain/**` 的
**既有行为零改动**，新增的只是"这句话之后该说什么"这一层判断。

**两条待定的实现取舍**（写在这里，实现时定，倾向 ①）：

1. **判据怎么来**：① 代码看得见的线索（问句形态）+ 已有的**输入类型**判断，拿不准再交给模型；
   ② 每次都多问模型一次（更准、多花钱）；③ 见问号就当问题（最省，但「下周三交提纲吗」这种自言自语会误判）。
2. **事实问题与"关于我"的先后**：先**追溯**、留档说没有时再交给那个 moment，是一条便宜且结构清楚的读法
   （问事实的时候自然不会被塞一条判断）；反过来先浮现会烧掉冷却。倾向先追溯。

**明确不做**：不做对话历史、不做多轮追问、不做打字机效果、不做"清空对话"这类聊天软件的家具 ——
产品是**陪伴**不是陪聊（`CONTEXT.md` 的 `_Avoid_`）。

**与 14 的关系**：两张票改动的地方几乎不相交（14 在 `linking.ts` 的阈值，15 在分发与页面），
但按本仓库的规矩**仍串行**：14 先做（已开），15 排在它后面。
