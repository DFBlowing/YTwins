# 15: 一个框 —— 把丢、问、浮收成一件用户做的事

**What to build:** 用户只看到一个输入框：随口丢什么都进同一个框。分不清"这是在丢碎片，还是在问一句"是
**产品**的事，不是用户的事 —— 所以这件事不该由用户选，也不该由页面猜。原话永远先成为一次**投递**
（原文保真落库），然后产品自己决定这句话之后还要说什么：问的是**留档**里的事 → **追溯**（照实陈述、
指出出处）；问的是关于**用户自己** → 同一个 moment 给**答案**；只是一句碎片 → 只有**投递**自己的回应，
外加（若带情绪）**浮**出来的那一条。三幕页原样保留，作为演示与回归的参照。

**Blocked by:** 07（追溯）、11（答案）、13（演示页与预置素材）

**Status:** ready-for-human

- [x] 一个输入框：没有页签、没有单独的「问」入口、没有类型／时间／标签控件。
      产品本身现在是 `/`（`src/web/index.html` + `one-box.ts`），三幕页一行未改地搬到 `/demo.html`（作者拍板）。
- [x] 任何原话**先落库**（`drop` 的保真承诺不变），用户当场拿到一句**回应**，以及（有的话）**事项**与**词条**。
      `deliver` 会等这次**读**落地（`drop` 不等）—— 分发要读**输入类型**，回应里也要带上事项与词条。
- [x] **分发是领域的规则，不是页面的 if。** 页面只把原话交给领域，然后照领域给的结论显示 ——
      落成一个**任务形状**的操作（名字按 `CONTEXT.md` 的词定：投递／追溯／浮现），
      而不是让页面自己拼 `drop` + `recall` + `surface` 三次调用。
      落地形状：`Domain.deliver(body) → { drop, speech }`，`speech` 是三取一
      （`recall` / `surface` / `none`）；路由本身是领域内部的 `readQuestionShape` + 端口 `judgeQuestion`。
- [x] **事实问题**：答得出就照实说并指出出处；答不出就明确说没找到。
      **问事实的时候不许塞一条判断** —— 这一轮不触发浮现。
      （领域检查里用「一有事可说就一定会说的材料」钉住：`provider.answers` 为空。）
- [x] **关于用户自己的问题**：走那个 moment 给**答案**（多条小结论汇成一句）；凑不出两条时退回**浮**出
      仅有的那一条（11 的退路不变）。**与 Comments 里倾向的 ② 不同，已改为只走 moment**，理由见下。
- [x] **碎片**：不追问、不装懂；带情绪时照旧**浮**一条（06 的时机、每轮最多一条、7 天冷却都不变）。
- [x] **分不清时不猜**：判不出是问题，就不当问题 —— 宁可少说一句，也不把自言自语当成提问。
      形态=statement 时**根本不问模型**；形态=unclear 且这次投递被读成 `emotion` 时也不问。
- [x] **端口要跟上**：新增端口方法 `judgeQuestion({ body, shape }) → { asks: false } | { asks: true, about }`；
      **两个 implementation 都实现了**（`fake-provider.ts` 与 `ai/llm-provider.ts`），
      12 的 `satisfies Record<keyof …, true>` 确实逼出了穷尽性（`real-provider.ts` 的 `LLM_OPERATIONS` 一漏就编译不过）。
- [x] **页面**：一条**投递** = 原话 + 它的回应 + 事项 + 词条 +（如果有）追溯的答复与出处／浮出来的那一条；
      下面仍是「接下来要做的 / 连起来的词条 / 画像」。
- [x] **三幕页一行不改**，仍然是演示与回归的参照；`tools/e2e-ticket-13.mjs` 与三幕相关的检查不动、仍全绿
      （文件 `git mv` 到 `demo.html` 只改了地址，内容一个字符没动；`main.ts` 一行没改）。
- [x] 领域测试新增 4 条钉住分发（碎片不触发答案、事实问题不触发浮现、答不出明说没找到、关于自己的问题给答案
      —— 含 11 的退路）；`src/domain/**` 的**既有**检查一行不改仍全绿（163 → 167）。
- [x] DOM 不自动测（spec 的测试决策如此），跨层取数用真 HTTP 的 e2e 覆盖（`tools/e2e-ticket-15.mjs`，10/10）。

**2026-09-19 — 实现完成（`Status: ready-for-human`）**

**做成了什么。** 领域多了一个任务形状的操作：`Domain.deliver(body) → { drop, speech }`。
`drop` 是这次投递本身（原话、回应、事项、词条，形状与 `/api/drops` 完全一样，刷新后读到的是同一个东西）；
`speech` 是三取一 —— `{ kind: 'recall', result }`（追溯）／`{ kind: 'surface', result }`（浮现或答案）／
`{ kind: 'none' }`（只有投递自己的回应）。**页面一次调用拿到全部**，`/api/deliver` 是它唯一的写入口；
三幕页那条 `POST /api/drop` 的形状一个字没动（e2e 里钉住了）。

**一处代价，写在明处：`deliver` 会等这次读落地，而 `drop` 不等。** 理由是两条：分发要读**输入类型**，
而这一页要把事项与词条跟回应摆在同一条投递里（不必再轮询）。代价是一个很慢或卡住的 provider 会让这一页
等 —— AI 层有 120 秒超时，超时退化成「这次没读出来」，投递本身早就落库了。三幕页那条路一个字没变。

**判据从哪来（Comments 第 1 条取舍的落点：①）。** 两层，第二层才花钱：

1. `src/domain/routing.ts` 的 `readQuestionShape(body)` 读**形态** —— 问号、或「怎么／为什么／哪／多少／
   是不是」这类只会在提问时出现的说法 → `question`；只有句尾「吗／嘛／呢」→ `unclear`；其余 → `statement`。
   `statement` **根本不问模型**（一串普通碎片零模型成本）。
2. 端口新增 `judgeQuestion({ body, shape })` → `{ asks: false } | { asks: true, about: 'records' | 'self' }`，
   由模型判定「这句是不是在问、问的是哪一类」。**判不出（或没有 provider）就当不是问题** ——
   `判不出是问题，就不当问题`是代码里的分支，不是约定。

**输入类型的用处只有一处**：形态是 `unclear`（句尾「吗」这种，提问与自言自语长得一样）时，这次投递若被
读成 `emotion`，**直接当碎片、不问模型** —— 「下周三交提纲吗」是自言自语。形态是 `question`（他自己标了
问号或用了一望即知的提问说法）时不论读成什么都交给模型：把真问题当碎片是唯一没有诚实退路的错法。
