# 05: 阈值汇集 —— 第一条小结论、画像与结论链

**What to build:** 在用户看不见的地方，当某个情绪或决策与足够多的**词条**相连、跨过**阈值**时，
自动汇集出一条说人话的**小结论**（例如「你似乎很想学吉他」），并把支撑它的词条一起存下来。
汇集有**防抖**：不在每次投递后立刻判定，而是「安静一段时间后」或「累积若干条后」触发，
避免几句互为上下文的话被过早汇集成错结论。用户能在页面上看到**画像**（= 小结论的集合本身，
不是另一份藏起来的模型）与**结论链**（默认只读，想看就能看），每条小结论都列出支撑它的词条。

**Blocked by:** 04（词条与链接 —— 把碎片连起来）

**Status:** ready-for-agent

> **先做一次 prototype 摸数值**（2026-09-15 定）。本 ticket 的三个常量 —— **阈值数值**、**防抖窗口**、
> 相关度分数口径 —— 靠读 spec 定不下来，它们要在真实词条与链接上推演才有手感。因此在写本 ticket 的实现
> **之前**，先用一次 throwaway prototype 回答四个问题：① 丢几句才该出结论、太早／太晚的边界在哪；
> ② 连续丢几句相关的话，合成一条对还是各自成结论对；③ 用「词条集合语义重叠」判同一主题，实际会不会把
> 两件不同的事判成同一主题；④ 支撑度 → 措辞强弱的映射，读出来是洞察还是别扭。
> 摸出的数值写回本 ticket 的常量，prototype 本身按 `/prototype` 的规矩留在 throwaway 分支、不进 `src/`。
> 问题 ③④ 的结论同时影响 **06**（浮现），做的时候一并带过去。

- [ ] **阈值**是数量门槛（足够多的词条连上来），不是时间门槛。
- [ ] 阈值未到时不出**小结论**；跨过阈值时出小结论，且该结论带完整的支撑词条列表。
- [ ] 阈值数值、相关度分数口径、防抖窗口由可配置常量承载；初始值以「demo 第三幕的预置数据必然触发、且不会每次投递都触发」为准。
- [ ] 防抖生效：几句互为上下文的连续投递不会在最后一句之后立刻汇集成一条错结论，而是在安静期或累积量满足后才判定。
- [ ] **小结论**是说人话的陈述句，用户能立刻判断它对不对。
- [ ] **画像**读出来的就是小结论的集合本身，不存在另一份用户看不见的模型。
- [ ] **结论链**默认只读，页面上可查看，并显示每条小结论的支撑词条以及它修订／被修订的关系。
- [ ] 用户能查看某条小结论是由哪些词条支撑的。
- [ ] 整个**沉淀**过程不需要用户参与，界面上没有需要用户维护的步骤。
