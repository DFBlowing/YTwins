# 14: 链接阈值 —— 对着真实 embedding 标定

**What to build:** 让「语义相近」这条**链接**在真实 embedding 上不再误连。先用真实模型量出一批**有标签**的
词条对的余弦分布，再据此重新定 `LinkPolicy` 的三段式边界（直连 / 灰区 / 不连）与灰区策略 ——
使已知的那条假链接不再直连，而真相关的词条照常连上。边界与策略仍然是**注入的值**
（`createDomain({ linkPolicy })`），不是写死在代码里的常量。

**Blocked by:** 04（链接的形状）、12（真实 embedding 可跑）

**Status:** ready-for-agent

- [ ] **先量，不许先改数值。** 标定脚本用真实 embedding（`YTwins_EMBEDDING=local`，
      `Xenova/multilingual-e5-small`）量一批有标签的词条对，打印每对的余弦值；
      样本与全部数值写进本 ticket 的 `## Comments`，脚本作为一次性件进 `archive/`（不进 git）。
- [ ] 样本至少三类：**正例**（真相关的对）、**负例**（已知假链接那对，以及明显不相干的对）、
      **硬边对**（同一次**投递**里一起说过、语义一般般的对 —— 它们不该指望相似边）。
- [ ] 把量出来的两个分布（正例 / 负例）摆给作者看，讲清**两种改法**的代价，由作者选：
      ① **放宽灰区**（把直连门槛提到实测正例的下沿之上、不连门槛提到负例的上沿之下，中间全部交给
      `judgeLink`）—— 三段式的设计意图，代价是每个灰对多一次调用（一次调用很便宜）；
      ② **换分布更开的 embedding 模型**（候选 `Xenova/bge-small-zh-v1.5`，实测分布 0.37–0.63，
      但要整体重新标定，而且它只覆盖中文，现在是多语言）。
- [ ] 已知的假链接不再直连：真实链路上 `琴行的帖子 × 下周三交提纲`（实测 0.852）不得成为**链接**，
      或至少不得以「语义相近」直连（走 `judgeLink` 由它判否是允许的）。
- [ ] 真相关的对仍然连得上：`期末怎么算分 × 平时分 40%`（实测 0.895）、`想学吉他 × 琴行的帖子`（0.882）
      这一类照旧成边，强度仍然可比。
- [ ] 04 定的规则一条不改：一对词条只有一条**链接**、**硬边覆盖相似边**、维度不同的两个向量不比、
      灰区才调 `judgeLink`；`LinkPolicy` 的形状（`directAtLeast` / `unrelatedAtMost` / `greyZone`）
      若需要增删字段，同样是注入的值。
- [ ] 领域测试**一行不改**仍全绿（阈值本就是注入的），并补 2–3 条钉住新边界的检查（成边 / 不成边 / 灰区问谁）。
- [ ] 演示模式不受影响：预置 provider 没有脚本化向量，语义那一半根本不会形成边
      （`tools/e2e-ticket-13.mjs` 已经钉住这一点：三幕里只有 `same-drop` 硬边）。
- [ ] 真实链路手工过一遍（要 key、要联网、要花一点钱）：丢几件真事，看「连起来的词条」里没有假链接；
      有 `judgeLink` 调用时，把它的判定与理由打出来给人看。

## Comments

**2026-09-17 — 开票（还没动工）**

**为什么有这张票。** 12 落地真实 provider 时实测到：`Xenova/multilingual-e5-small` 的余弦分布**很挤** ——
相关对 0.88–0.91、不相关对 0.84–0.88（`query: ` 前缀，三组样本见 `NEXT.md`「下一步」第 2 条与 ticket 12 的
Comments 第 9 条），而 `src/domain/linking.ts` 的默认三段式是「**≥ 0.85 直连 / ≤ 0.7 不连 / 中间问
`judgeLink`**」。两个分布**重叠**，所以：

- 把直连门槛提到 0.91 以上 → 会漏掉一部分真的相关对；
- 把不连门槛压到 0.84 以下 → 灰区变宽，更多对要走 `judgeLink`（每次调用很便宜，这是设计意图）；
- 只要**直连**这一档还留在重叠区里，就一定会误连 —— 已经抓到了一条：`琴行的帖子 × 下周三交提纲 = 0.852 → 直连`。

**这不是 12 的 bug，也不是 13 的边角料。** spec 把「阈值 / 灰区边界 / 主题重叠比例」明确列为**尚未定值的
参数**，由可配置常量承载、之后再按真实数据校准；13 的演示走预置 provider、不经过 embedding，所以第三幕
不会挂着假链接。这一票就是那次校准。

**开工前先问作者的一件事**（NEXT 第 2 条要求）：走 ① 放宽灰区、让 `judgeLink` 判，还是走 ② 换 embedding
模型。量完之后带着分布图去问，不预设。

**量什么，怎么算数。** 标定要的是**同一批词条对在真实模型下的余弦值**，样本来自这个产品真实会遇到的
词条（用户自己的说法），不是通用语料。判据是两条：① 已知假链接那对不再直连；② 已知真相关的那几对照旧
成边。除此之外的一切数值都是可调的。

**这一票不动的东西**：`LinkPolicy` 的位置与形状（`src/domain/linking.ts` 注入 `createDomain`）、
`same-drop` 硬边（零模型，永远最强）、演示模式与预置素材。
