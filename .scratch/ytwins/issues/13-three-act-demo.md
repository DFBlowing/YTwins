# 13: 三幕 demo —— 预置数据与可重复

**What to build:** 三个动作在预置数据上稳定、可重复地跑出来：① **丢** —— 丢一段含老师讲的评分标准 +
一句情绪的杂乱输入，不选类型、不填时间，自动分出**事项**与**留档**；② **问** —— 以「几天后」的视角问
「期末怎么算分」，准确答出并指出源自哪次**投递**；③ **浮** —— 再丢一句情绪化输入，浮出一条**不确定语气**
的**小结论**，由**预置的足够词条**支撑。页面同时明确告诉用户哪部分数据会离开这台机器。

**Blocked by:** 06（浮现 —— 情绪投递时的那一条）、07（追溯 —— 问一件旧事，答得准并指出出处）、
12（真实 provider —— 云端 LLM + 本地 embedding + 可切换）

**Status:** ready-for-human

- [x] 第一幕：一段含评分标准与一句情绪的杂乱输入，不选类型、不填时间，自动分出**事项**与**留档**。
- [x] 第二幕：以「几天后」的视角问「期末怎么算分」，得到准确回答并看到它源自哪一次**投递**。
- [x] 第三幕：再丢一句情绪化输入，浮出一条有足够**预置词条**支撑的**不确定语气**小结论。
- [x] 三幕共用同一套预置数据，且该套数据与领域测试使用的预置数据是同一份。
- [x] 三幕可以连续重跑而结果不变（同一套预置数据、同一条链路，不靠运气）。
- [x] 页面明确告知哪部分数据会离开这台机器（demo 阶段：送去云端 LLM 的原文），embedding 留在本地。
- [x] 整个 demo 不需要账号、不需要联网完成注册；不做系统级推送与提醒。
- [x] 三幕的演示脚本以中文写进仓库，供日后复现。

## Comments

**2026-09-17 · 落地成的样子**

**1. 开工前问过作者的四个问题**（答案就是这一票的形状）：

- **演示走哪条 provider？** 演示路径走**预置 provider**（`YTwins_PROVIDER=demo`），真实 provider 仍是
  产品的默认。只有预置那条能同时满足票面的「同一套预置数据」与「重跑结果不变」；两条路都跑了一遍，
  实测见第 8 条。
- **「预置数据」指什么？** 演示开始前把素材**作为真实投递**播进库（每件事先说到 2 次），现场每一幕只丢
  一次。没有这两次，「同一件事被提起 3 次」的阈值永远不会跨过。
- **连续重跑怎么做？** 页面底部一个「重新开始演示」（**两步确认**，和删除一样），配一条**只在演示模式下
  存在**的服务端路由。
- **`LinkPolicy` 阈值与真实 embedding 对不上（NEXT 第 2 条）怎么办？** 这一票不动它，留成 13 之后的
  一张票；13 的演示走预置 provider，不经过 embedding，第三幕不会挂着假链接。

**2. 一套预置数据，一个模块：`src/domain/preset.ts`。** 它同时是「素材」「读素材的 provider」「把素材
铺进库」三件事的唯一落点：

- 放 `src/domain/` 而不是 `src/web/`，理由是票面那句「与领域测试使用的预置数据是同一份」：领域测试
  （`src/domain/domain.test.ts`）要 import 它，而依赖方向 `src/web/ → src/domain/` 不允许反过来。
  `src/web/demo-provider.ts` 因此**删除**，内容并入 —— 留一份在 web 里就是票面要防的那种漂移。
- **台词由服务端给页面**（`GET /api/demo`）：第一幕的输入、第二幕的问题、第三幕的句子都从素材读出来，
  页面连占位文本都不抄第二份（原来 `index.html` 的 placeholder 是仓库里唯一一处「预置字符串写两遍」，
  已在注释里承认过，这次一并消掉）。
- 素材表里每条 fragment 带自己的 `terms` / `anchor` / `reply`，`PRESET_LEADS` 只是这张表的一部分；
  读一次表，铺一次库，没有第二处清单。

**3. 预置素材的形状。** 4 条 **leads**（关于期末那件事 2 条、关于睡不好那件事 2 条）+ 现场三句。两条
leads 都用**普通投递**的路径进去（`domain.drop` + `domain.extract`），所以它们有回应、有词条、真的归并成
matter —— 三幕跑的是真实链路，不是特例状态。

第二幕的问题要找的三个字符串（`期末怎么算分` / `平时分` / `期末考 60%`）**刻意不出现在 leads 里**：
于是答案的出处就是第一幕刚丢的那一条，票面那句「指出源自哪次投递」才是一条可核对的断言，而不是
「好几次里挑一次」。

**4. 「下周三」不写死。** 事项的到期时刻由代码按**素材被认为说出的那一天**算成「下一个周三 09:00」
（真 provider 也是把相对时间按今天换算 —— `llm-provider.ts` 的 prompt 里就写着「今天是…」）。写死一个
日期过几天就会变成「已过期」，而素材里说的明明是「下周三」。

**骰子在演示模式下钉死**（`random: () => 0`）：哪条开头、这一轮用不用这次机会都是 roll，
「重跑结果不变」不能靠运气。产品本身仍然用真骰子。

**5. 重置 = 清空 + 重新铺，两个都在该在的地方。**

- `DropStore.clear()`（新增）：子表→父表顺序 DELETE，`settle_state_` 复位成新库的样子，**一个事务**；
  它是 store 的能力，**不是** domain interface 的操作 —— 领域接口是「产品会做的、任务形状的事」，
  「整个清空」不是其中之一。
- `seedPreset(domain)`：只走 `domain.drop` / `domain.extract`，不碰存储内部。
- **演示模式默认用自己的库 `data/demo.sqlite`**：那个按钮清空的是它，不是你平时丢东西进去的
  `ytwins.sqlite`（`YTwins_DB` 设了就以它为准，启动日志会写明用的是哪个文件）。
- 路由只在 `YTwins_PROVIDER=demo` 时存在：真实服务器上 `POST /api/demo/reset` 是 **404**，
  `/api/demo` 回 `{demo: null}` —— 没有一种请求形状能在别人真用的服务器上清空全部素材。页面两步确认。

**6. 数据边界从配置读出来，不从页面抄。** `src/web/privacy.ts` 把解析出来的 `ProviderConfig` 读成
「离开这台机器的 / 留在这台机器的」两张清单，页面从 `GET /api/privacy` 拿：

- 演示模式：`leaves` 为空，页面明说「什么都不离开这台机器」（预置 provider 连网络都没有，这比「模型是
  本地的」更强）。
- 真实模式：指名端点与模型（`api.deepseek.com` 的 `deepseek-flash`）、指名**哪部分**是原文、说明
  embedding 在本机 CPU 上算、key 只在 `.env` 里且页面拿不到。
- 服务端没被告知边界时返回 404，页面显示「这次没读到数据边界」——**不会**渲染成「什么都不出去」。
  这是这一页唯一一处「读不到」与「没有」必须分开的地方：反过来就是这条披露在骗人。

**7. 页面上的两节**（三幕页签下方）：三幕的台词（含「重新开始演示」）与数据边界。两节都常驻，所以
站在任何一幕都能看到边界；demo 那一节只在演示模式下出现（真实模式里没有脚本可给，摆一个禁用按钮只会
让人以为有）。

**8. 两个 provider 都跑了一遍（NEXT 第 3 条要求），实测记录 2026-09-17：**

- **真实链路**（云端 DeepSeek + 本地 embedding）：第一幕抽出的事项与词条与预置素材**完全一致**
  （5 个词条，「下周三」算成 `2026-09-23`），回应是先接情绪的那一句；第二幕答对了评分口径
  （「平时分 40%，期末考 60%，下周三交提纲。」）并只引那一次投递。但：第三幕要**现场丢三次**同一句才
  跨阈值（真实链路没有 leads），措辞每次不同，而且要 key、要联网。
- **一处真实的竞态**（顺手查清，不是 13 的 bug）：跟在一句投递后面的那次 settle 可能跑在「读出」与
  「归并」之间 —— `drop_.input_type`（读出的标志）先于 attachment 落库，所以页面/脚本看到 `extracted`
  时那一条可能还没进 matter。我的一次性驱动脚本因此看到 `nothing-to-say`；把同一条链路用
  `domain.extract()` 正确等待（领域测试就是这么做的）之后，真实 provider **确实**浮出了结论
  （「我说不好，不过你似乎被这一周的睡不好缠着，到现在还没能缓过来。」）。页面每 250ms 重试三次，
  正是覆盖这个窗口的。
- **结论**：演示走预置 provider；真实 provider 仍是默认，它的语义调优不在这一票里。
- 驱动脚本是 `archive/ytwins-13-real-run/` 下的一次性件，`archive/` 不进 git。

**`/code-review` 两轴结论与按结论做的处理**

Spec 轴 —— 四条**属实且已改**（评审看到的是票面更新前的快照，那条「票面没勾 / 没有 Comments」已解决）：

- **占位文本的陷阱（最重，已改）**：页面原来把占位写成 `` `比如：${acts.drop}` ``，而演示脚本写「照抄占位
  文本」—— 照抄会多出一个「比如：」，而预置 provider 按**整串相等**匹配，于是第一幕什么都读不出来、
  二三幕跟着塌。现在演示模式下占位文本**就是台词本身**（无前缀），`index.html` 里的静态例子改成纯说明
  文字，不再是与台词相近的第二份例子。
- **「不联网」原来只是文案（已改）**：e2e 原本只断言那句话里含「不联网」。现在 e2e 在起服务前包了
  `globalThis.fetch`，把非 `127.0.0.1` 的请求全记下来，三幕跑完断言为空 —— 「不联网」成了**代码事实**。
- **「没有注册 / 推送路由」原来用错误的理由通过（已改）**：任何未匹配的非 GET 都回 405，所以拿任意路径
  都能「通过」。顺带查出一个真问题：**未知的 `GET /api/*` 原来会落到静态兜底、回 200 的 HTML** —— 既让
  这条断言无从下手，也会把 HTML 塞给以为是 JSON 的调用方。现在 `/api/` 命名空间下的未知 GET 回 404，
  e2e 对四个名字各查 GET（404）与 POST（405）。
- **第二幕的天数原来用字面量断言**（`还有 3 天`），只在 UTC+8 这种时区成立；已改成断言答案的**形状**
  加上「视角近一天就少一天」这条**性质**（领域测试与 e2e 都改），演示脚本也把「N 跟着提问的时刻走」
  写明。

Standards 轴 —— **改了四条**：

- `CLEAR_ORDER` 是 schema 的第二份知识（后加一张表就不会跟上）：改成从 `sqlite_master` 读表名
  （`settle_state_` 除外），顺序由 schema 自己给 —— 现有引用都带 `ON DELETE` 动作，所以删哪张都不会被
  挡住，而**后加的无动作表会当场报错**，不会被悄悄漏掉。并补了一条负向检查：「重置之后库真的是空的
  （投递/事项/链接/小结论/时间线五个面都空），而且还能再用」（原来只有「三幕跑两遍」间接观察）。
- e2e 那四条路由断言的**名与实不符**（见上）。
- 两个只有本文件在用的 composer 原来 `export` 了（Speculative Generality）：收回成模块私有。
- `PRESET_ITEM_TEXT: string` 的显式标注与本文件其它常量不一致；顺手加 `PRESET_OUTLINE` 把「下周三 +
  那条事项文案」收成一处，`composeRecallAnswer` 也从它读 weekday。

Standards 轴 —— **保留三条并写明理由**：

- **e2e 里的预期台词不 import 常量，而是写成字面量**：import 过来的预期与被测实现同源，等于恒真
  （TDD 那条「期望值不能由实现重算」）；e2e 另有一条「服务端给页面的三句 === 预置素材」的恒等断言，
  两条合起来才是「页面跑的是素材，而且素材还是这些话」。所以评审说的「改 preset 后 e2e 照样绿」不成立：
  改素材会让字面量断言红，而那正是想要的。
- **预置 provider 跟着素材留在 `src/domain/`**，不搬去 12 定的 `src/ai/`：`src/ai/` 放的是**跟外界打交道**
  的实现，这一个架在 `fake-provider.ts`（ticket 01 起就在 domain、专供领域测试驱动）之上。拆开会要么让
  测试够不到它，要么让测试自己再造一个 provider。理由写进模块头。
- **日期口径两份**（`preset.ts` 里答案的一句话 vs `main.ts` 的 `dueLabel` 列表标签）：一份是产品对用户素材
  说的话，一份是页面给一行加的标注，允许措辞不同。已在函数注释里写明哪个是哪个。
