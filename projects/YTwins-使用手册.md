## 1. 这是什么

你把日程、灵感、情绪**随口丢进来**，不用分类、不用打标签、不用填时间。
它接住，在你看不见的地方把碎片慢慢连起来，攒够了才浮出一句简短的话。

**它不是**：不是聊天助手（不留对话）、不会主动弹通知给你、不给你打分也不让你点赞。

## 2. 第一次用（只做一次）

1. **确认 Node 够新**：终端里跑 `node --version`，要 **22.18 以上**（这台机器是 v22.23.2，没问题）。
   太老的话启动时会报语法错误 —— 升级 Node 就好。
2. **装依赖**：`npm install`（装过一次就不用再装）。
3. **配钥匙**：把仓库根的 `.env.example` 复制成同目录的 `.env`，按里面的说明只填两行
   （选哪家模型 + 这一家的 key）。**`.env` 不进 git，也不会被浏览器看到**；但它是你的钥匙，
   别贴给别人、别截图。
4. **把页面构建出来**：`npm run build:web`（页面改过之后也要重跑这一条）。
5. **起服务**：`npm run server`。

打开 `http://127.0.0.1:5273/` 就是产品本身。这个服务**只在本机可见**，同一局域网里别人打不开。

**起服务的那个终端别关**：它一边跑服务，一边告诉你现在用的是哪个模型。正常时它先打印这样三行
（下面取自本机，模型与 key 状态会随你的配置变）：

```text
预设 deepseek（云端）：https://api.deepseek.com · deepseek-flash（key 已配置）
本地 embedding：Xenova/multilingual-e5-small（缓存在 …/data/models，第一次使用会联网下载）。
YTwins 在 http://127.0.0.1:5273 上运行（仅本机可访问）
```

第一行就是「怎么确认自己换模型换成功了」的唯一答案：**以这行日志为准，不要靠感觉**。

## 3. 日常怎么用

### 一个框，三种丢法

页面上只有一个输入框。**你不用选类型**，它自己分：

| 你丢进去的 | 它会做什么 |
|---|---|
| 一句碎片（今天发生了什么、什么心情） | 回你一句，顺手记下事项和词条 |
| 问一件你确实说过的事（如「期末怎么算分」） | 答出来，并指出**这话出自哪一次投递**，可以逐字核对 |
| 问一句关于你自己的话（如「你觉得我最近怎么样」） | 把几条小结论汇成一句 —— 凑不出来就只浮一条，或干脆不说 |

### 页面上有几块，各看什么

- **接住了什么**：每次投递的原话、它的回应、它接住的事项与词条。
- **接下来要做的**：有时间的事项自动排好；没解析出时间的落在「待安排」，不会被丢掉。
- **连起来的词条**：哪两个词条连上了、为什么连、强度多少。
- **画像**：它对你攒下来的小结论 —— 画像就是这些结论本身，没有另一份藏起来的模型。
- **哪些数据会离开这台机器**：这一节由**服务端按本机实际接线**读出来，页面不写死文案。
  **想确认隐私就只看这一节**。

### 你能做的几个轻动作

- 觉得某条小结论不对 → 标「不对」。它不会改写那条，只在旁边添一条记录；旧的那条一字不动。
- 想补一句自己的话 → 写在结论旁边，那句话本身又算一次投递。
- 想删掉某次投递 → 点删除。它是**两步**的：先告诉你「有 N 条小结论是从这句来的」，再由你选
  「一起删」「只删原文」还是「保留」。这是唯一会一次清空很多东西的动作。

### 合理的期待（不然会以为它坏了）

- 同一件事**要提起 3 次**才够格沉淀出一条小结论 —— 说一次两次它只是记着。
- 同一个主题**7 天内只浮一次**，每轮最多说一条。
- 它**不存对话**：追问的答复和浮出来的那句只在那一次页面上；刷新后留下的是你的投递和画像。
  这是有意的 —— 它是陪伴，不是陪聊。

## 4. 换模型（最常问的一件事）

**换一家 = 改 `.env` 里两行 + 重启服务。** 调用路径不用动。

```ini
YTwins_LLM_PRESET=deepseek      # 换成 deepseek / gemini / opencode / ollama / custom 之一
YTwins_LLM_API_KEY=…            # 写这一家的 key
```

- 每个预设**自带端点、默认模型、key 放在哪个请求头里**，所以换家只改这一行的值。
- 预设表（含每条的出处）在 `.env.example` 里；想连没列出的服务用 `custom`，
  那时端点和模型名都要自己写出来。
- 用**本机模型**（Ollama 一类）不需要 key：预设写 `ollama` 即可，你的话就不出这台机器。
- 改完**必须重启服务**，然后看启动日志第一行确认。

**写矛盾了它会拒绝启动**，并且明确告诉你是哪个变量 —— 这是好事：
把云端端点说成本机，等于骗你说「你的话没离开这台机器」，所以它宁可不开。

> **embedding 不在「只填一个 key」的承诺里。** embedding 是「判断两个词条像不像」用的另一套模型。
> 判断「像不像」的数字是对着现在这一个 embedding 实测标定出来的，**换它等于换一套标定**
> （换错会让该连的连不上、不该连的连上）。所以：想换的话先读
> `.scratch/ytwins/issues/14-link-threshold-calibration.md`，别顺手改。

## 5. 演示模式（给人看的那一份）

演示**不联网、不花 key、每次说一样的话**，但只认写死的那几句台词。

```powershell
$env:YTwins_PROVIDER = "demo"
npm run server
```

- 演示页是 `http://127.0.0.1:5273/demo.html`（产品本身在 `/`，两页共用同一套逻辑）。
- 演示模式下页面输入框上方会自己声明「这个服务只认页尾那三句台词」—— 正常的，不是坏了。
- 演示用**自己的库** `data/demo.sqlite`，页面底部那个「**重新开始演示**」清空的是它，
  碰不到你平时丢的东西（启动日志会写明清的是哪个文件）。
- 台词、预期看到什么、台下问题怎么答：`docs/ytwins/demo-script.md`。

## 6. 有问题怎么办

### 症状 → 怎么办

| 症状 | 多半是什么 | 怎么办 |
|---|---|---|
| 东西丢进去了，但一个词条都没有；追问说「问不到」 | key 没配、或配错了端点 | 看 `.env` 两行 → 重启 → 还是不行就跑 `npm run smoke` 验证 |
| 起服务直接退出，打印一段中文报错 | 配置写矛盾了 | 报错里点名了是哪个变量，按名字去 `.env` 改 |
| 页面打不开 / 提示「页面尚未构建」 | 页面还没构建，或改过页面没重建 | `npm run build:web`，然后刷新 |
| 起服务报端口被占用 | 已经有一个服务在跑（或别的程序占着 5273） | 关掉旧的，或换个端口：`$env:YTwins_PORT="5274"; npm run server` |
| 第一次用很慢、卡住不动 | 正在下载本地 embedding 模型（约 120 MB，进 `data/models`） | 等它下完；下载不动就换镜像：在 `.env` 加 `YTwins_EMBEDDING_HOST=https://hf-mirror.com` |
| 回话很慢或超时 | 云端模型慢 | 在 `.env` 加 `YTwins_LLM_TIMEOUT_MS=180000`（单位毫秒），重启 |
| 连起来的词条太多、明显不相干 | 是**参数**问题，不是故障 | 见 [§7](#7-调参数想改它什么时候说话)，先读那条的说明再动 |

### 三步排查法

1. **看启动日志**（起服务那个终端）：它说现在用哪家模型、key 配没配、用的哪个库。
2. **验证接线**：`npm run smoke` —— 用真实 `.env` 打一遍模型和 embedding，打印回来什么。
   只测一半就加参数：`npm run smoke llm` 或 `npm run smoke embedding`。
3. **怀疑数据而不是代码**：`data/` 下的 `.sqlite` 就是你的全部内容（见 §8）。

## 7. 调参数（想改它什么时候说话）

这些是**一个数字一个文件**的旋钮，改的是它的脾气，不是修 bug。当前值都写在文件里的注释旁边。

| 想改什么 | 改哪里 | 注意 |
|---|---|---|
| 同一件事要被提起几次才出小结论 | `src/domain/conclusions.ts` | 现在是 3 次。调小它变敏感，调大它变迟钝 |
| 同一主题隔多久才能再说一次 | `src/domain/surfacing.ts` | 现在是 7 天 |
| 这一轮到底说不说、最多汇几条 | `src/domain/surfacing.ts` | 想让它「更少、更意外」就调这里 |
| 两个词条算不算「连上」 | `src/domain/linking.ts` | 两个数字，是**实测标定**出来的；动之前先读 §4 那条提醒 |
| 它说话的语气规则 | `src/domain/parent-voice.ts`（规则来源：`docs/ytwins/parent-voice-principles.md`） | 改这里等于改它的性格 |
| 换模型 / 换端口 / 换库文件 / 超时 | `.env`（模板见 `.env.example`） | 改完重启服务 |

**改参数的规矩：一次只改一个，改完跑一遍回归，再看效果。** 一次改两个，出了问题你分不清是谁干的。

改完怎么算「没改坏」：`npm run test`、`npm run test:ai`、`npm run typecheck`；
更完整的回归清单在 `docs/ytwins/demo-script.md` 的 §6 与 `tools/README.md`。
**这些是给你自己用的开发动作** —— 只想用产品的话，跳过这一段。

## 8. 你的数据在哪

| 路径 | 是什么 | 能不能删 |
|---|---|---|
| `data/ytwins.sqlite` | **你平时丢进去的全部内容** | 删掉 = 从零开始（先关服务再删） |
| `data/demo.sqlite` | 演示模式自己的库 | 删掉无所谓，演示会重新铺 |
| `data/smoke.sqlite` | 冒烟脚本用的库 | 删掉无所谓 |
| `data/models/` | 下载下来的本地模型缓存 | 删掉会重新下（约 120 MB） |
| `.env` | 你的 key 与配置 | **别删、别外传**；丢了就重新填 |

`data/` 与 `.env` 都不进 git —— 它们只是这台机器上的东西。备份就是复制这几个文件。
